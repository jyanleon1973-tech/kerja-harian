# 3D 人形・3D スキー板の切替表示 — 調査・実現可能性・実装計画

作成日: 2026-11-01

## 1. 現在の 2D 解析データと、3D 表示に必要なデータ（手順 1）

| 既にあるもの | 出所 | 3D 表示への使い方 | 限界 |
|---|---|---|---|
| 2D 関節 33 点（正規化座標、平滑化前後）と関節ごとの確からしさ `q` | `perframe` → `temporal` | 3D 復元の拘束（再投影の整合）、信頼度 | 奥行きなし |
| BlazePose GHUM の 3D「world」座標（腰中点原点、体型正規化 m、平滑化後 `worldS`） | MediaPipe | 3D 姿勢の初期値。関節可動域・骨長・時系列・板接続の拘束で補正して使う | 単眼回帰で奥行き誤差が大きく、深い内傾・クローチングで崩れる。実寸ではない。原点が腰なので選手の移動は含まない |
| 撮影方向（側面/正面/背面/斜め）、カメラの平行移動量、カメラ補正済みの腰の画像軌跡 | `camera` | 3D 世界座標の向き付け、選手の移動（画像面内）、「撮影されていない角度」の判定 | ズームは未補正。奥行き方向の移動は不明 |
| 板の 2D 線（角度・両端の見かけの長さ・信頼度） | `ski` | 板の 3D 向きの拘束（2D 再投影の一致）、ブーツ位置 | 側面では 3D 向きが決まらない（どの水平方向も画面では水平線） |
| ターン方向・局面、切り替え時刻 | `turns` | 3D 表示の局面ラベル、板の軌跡の区切り | 推定 |
| 推定重心（2D）、重心移動ベクトル、身体運動指標、荷重傾向（未検証） | `metrics` / `vectors` | 3D 空間の重心球・矢印 | 荷重は未検証（参考表示のみ） |

足りないもの: 実寸スケール、奥行き方向の選手移動、雪面（斜度・向き）、カメラの内部パラメータ、板の 3D 向き（側面撮影時）、板のたわみ・エッジ角（単眼では測定不可）。

## 2. 3D 復元の実現可能性と限界（手順 2）

**結論**: 単眼の SL/GS 映像から「動画と一致する 3D 人形」を作るには、(a) 時系列を使う 3D 姿勢推定モデル、(b) 人体の関節可動域・骨長の拘束、(c) 板と雪面との接続拘束、(d) 奥行きの不確実性の明示、の 4 つが必要で、どれか 1 つでは不十分。以前の人形が不自然だったのは、(a) が BlazePose 単体で (b)(c) がなく、(d) もなかったため。

| 項目 | 実現可能性 | 条件・限界 |
|---|---|---|
| 関節角（膝・股関節・前傾・ひねり）の 3D 再現 | 中〜高（撮影方向で測れる成分は 2D と一致させられる） | 画面に直交する方向の成分は推定。正面撮影での前傾、側面撮影での内傾は信頼度が下がる |
| 深い内傾・外向傾・クロスオーバー | 中 | 時系列モデル + 拘束で改善するが、雪煙・重なりでは崩れる。信頼度を表示 |
| 選手の 3D 移動軌跡 | 低〜中 | 画像面内はカメラ補正で可、奥行きは体格の見かけの大きさの変化から粗い推定のみ |
| 板の 3D 位置・間隔 | 中（足部 3D から） | 実寸ではなく体格比。板の向きは正面・背面で良く、側面では進行方向に揃える推定 |
| 板のたわみ・エッジ角 | **不可** | 表示しない（すねの傾きを「角付けの目安」としてのみ） |
| 撮影されていない角度からの姿勢 | 推定 | カメラ方位と視点の差が 30° を超えたら「推定視点」と表示 |

### 候補となる 3D 姿勢推定技術（サーバー側で比較する）

| 技術 | 種類 | 入力 | ライセンス | 所見 |
|---|---|---|---|---|
| BlazePose GHUM（現行） | 単フレーム 3D 回帰 | 画像 | Apache 2.0 | 軽いが単眼回帰。拘束と時系列補正を加えて使う（本セッションで実装） |
| RTMW3D / RTMPose3D（MMPose） | 単フレーム 3D（全身） | 画像 | Apache 2.0 | RTMPose 系と同じ基盤で統合しやすい。要 GPU、未検証 |
| MotionBERT | 2D 系列 → 3D 系列（リフティング、時系列） | 2D 関節列 | Apache 2.0 | 2D の品質に依存。時系列で安定。要重み入手・検証 |
| VideoPose3D | 2D 系列 → 3D 系列 | 2D 関節列 | CC BY-NC 4.0 | 非商用。製品用途では不可 |
| HMR2.0 / 4D-Humans、WHAM | 人体メッシュ（SMPL）フィッティング、WHAM は世界座標の軌跡も | 画像 / 動画 | コードは MIT 等だが **SMPL モデルは非商用ライセンス** | 商用利用には SMPL の商用契約が必要 |
| 多視点 / IMU | 校正済み複数カメラ、慣性センサー | — | — | 精度は高いが撮影条件が変わる。検証用の正解作りに向く |

推奨: Phase 3 で RTMPose（2D）を導入したうえで、**MotionBERT 系のリフティング + 本セッションで実装する拘束付き補正**を第一候補、RTMW3D を第二候補として、同じ検証セットで比較する。SMPL 系は商用ライセンスを確認してから。

## 4. 3D 復元の設計（サーバー `pose3d` 段階）

1. **入力**: `worldS`（BlazePose 3D、腰原点）、`kpS`（2D）、`q`、骨長の時系列、撮影方向、カメラ補正済み腰軌跡。
2. **骨長の正規化**: 各骨の長さを動画全体の中央値に揃える（単眼回帰の伸び縮みを抑える）。
3. **関節可動域の拘束**: 膝は蝶番（伸展 0°〜屈曲 160°、過伸展を禁止）、股関節の屈曲・外転の範囲、足首の範囲。範囲外は最近傍へ射影。
4. **時系列補正**: One Euro（前後方向平均）で急な動作を残しつつ揺れを抑える。1 コマだけの 3D 外れ値は補修。
5. **雪面・接地**: 足部の最下点を窓の中央値で地面に合わせる。両板が接地している前提で、ブーツ底を地面に置く（ジャンプは信頼度を下げる）。
6. **向きと移動**: 骨盤の向きで前方を定め、カメラ補正済みの腰の画像軌跡から画像面内の移動を与える。奥行きの移動は体格の見かけの大きさから粗く推定し、低信頼度を付ける。
7. **信頼度**: 2D の確からしさ、骨長の逸脱、再投影誤差（3D を 2D に投影して観測 2D とどれだけ合うか）、視線方向と関節面の角度（画面に直交する成分の割合）から 0〜1 を算出。コマごとに表示する。
8. **出力**: 関節 3D（m 相当、体格比）、地面高、根の位置、信頼度、拘束で修正した量、フラグ（左右交差・ジャンプ・再投影誤差大）。

## 5. 品質検証（§9）の方法

- 検証セット: 実際の SL・GS 映像（側面、正面、背面）から `server/tools/eval.py extract` でコマを抜き、人が関節・板の両端・左右・ターン方向を付ける。
- 項目: 2D 再投影誤差（3D を投影して正解 2D と比較）、左右逆転率、膝角の妥当性（範囲外の発生率）、ブーツと板の離れ（ブーツ中心と板の線の距離）、左右の板の交差率、板の向きと 2D 線の角度差、コマ間の 3D 関節の飛び（身長比/秒の分布）、全モードの表示コマ番号の一致。
- 判定: 3D の見た目が滑らかでも、再投影誤差と左右逆転率が基準を満たすまで「一致」とは言わない。基準値は検証セットができた時点で決める。

## 6. 必要な承認・資材

- GPU クラウド（RunPod Serverless または Modal）の利用承認（Phase 3 と共通）。
- SL・GS の実映像（側面・正面・背面を各 1 本以上）。
- 3D モデルの重み（MotionBERT / RTMW3D）の入手とライセンス確認。
