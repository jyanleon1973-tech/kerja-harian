# 荷重ベクトル可視化と WC 映像活用 — 分類と改修計画

作成日: 2026-11-01　関連: `docs/wc-reference-and-load-validation.md`（参考映像・文献・検証方法）、`docs/phase2-report.md`

## 0. 最重要原則

実測していない荷重を、測定したかのように表現しない。表示する矢印・グラフには「何の量か」「観測か推定か」「検証済みか」を必ず付ける。

## 1. 物理量の区別と、現在の映像から得られるもの

| # | 量 | 単眼動画のみ | 校正・3D 復元があれば | センサーが必要 | 備考 |
|---|---|---|---|---|---|
| 1 | 身体重心の移動方向 | **可（画像上）**。カメラ動作を補正できればコース座標に近づく | 可（実空間） | — | 推定重心（質量比モデル）の 2D 位置の時間微分。固定カメラ以外は「見かけの移動」 |
| 2 | 身体重心の加速度 | 条件付き（ノイズが大きい、画像上のみ） | 可（実空間、m/s²） | — | 2 階微分は揺れに弱い。向きの傾向までが限界 |
| 3 | 重力の方向 | 不可（画像の鉛直で代用、斜度・俯角で数度〜十数度ずれる） | 可（雪面・鉛直の校正） | — | 校正点（ゲート・ストック・雪面線）の入力で改善 |
| 4 | 雪面からスキーへの接触反力 | **不可** | 条件付き（質量・3D 加速度・雪面法線・空気抵抗の仮定が必要） | 可（力センサー付きビンディング） | モード C。データが揃うまで使用不可 |
| 5 | スキーから雪面への力 | **不可** | 同上（4 の反作用） | 可 | — |
| 6 | 左右スキーへの荷重配分 | **不可**（身体の傾き・膝の屈伸は相関があるが配分は決まらない） | 不可（力の総和は分かっても左右の分配は決まらない） | 可（圧力インソール、左右の力センサー） | モード B の検証対象。検証前は % を出さない |

## 2. 要件の分類

### A. 既存システムで実装できる（本セッションで実装）

- **モード A: 重心移動ベクトル**。推定重心の画像上の移動方向と速さ（身長比/秒）。サーバー解析ではカメラの平行移動を差し引いた値、ブラウザ内解析では「画像上の見かけの移動」と明記。長さ・太さ・色は相対的な速さ、透明度は信頼度（関節の確からしさ、補間、カメラ応答）。「推定」ラベル付き。
- **身体運動指標の時系列グラフ**（荷重グラフではない）: 外脚・内脚の膝屈曲、脚の伸展速度、推定重心の左右位置（正面・背面）または前後位置（側面）、重心の移動速さ、切り替え位置。荷重の縦軸（N・体重比・%）は使わない。
- **外脚・内脚の判定**（ターン方向から）、左右膝屈曲、骨盤と足部の相対位置、重心位置、板の方向変化（検出できたコマ）、ターン局面: 既存の指標を矢印・グラフに接続。
- **モード B の枠組み**: 荷重傾向スコアの入力（上記の運動指標）と出力の形式、「未検証」フラグ。表示は既定で無効、「参考表示（未検証）」として灰色の矢印のみ有効化できる。色による強弱表示は検証後まで行わない。
- **モード C の入口**: UI 上は使用不可（理由を表示）。
- **WC 選手との比較の基礎**: 解析結果 JSON を参照データとして読み込み、同じ撮影方向・同じターン局面の平均値を並べる。撮影方向が違う場合は数値比較を出さず警告する。WC 選手を唯一の正解としない注記。
- **再生・スロー・コマ送り・書き出し**: 矢印・グラフは既存の同期機構（コマ番号）に乗せる。書き出し動画にも矢印を描く。

### B. 追加の AI 学習・開発が必要

- 板の専用検出（トップ・テール・ブーツ）: 板の方向変化を安定して取るために必要。学習データの作成から。
- 高精度の姿勢推定（RTMPose / ViTPose、GPU）: 深い内傾・クローチング・雪煙での関節精度。
- 3D 運動復元（単眼 3D 姿勢 + 雪面校正）: モード C と重心加速度の実空間化の前提。
- 荷重傾向モデル（モード B）そのもの: 身体運動指標 → 左右荷重傾向 の対応は、センサーで取った正解データで学習・検証して初めて有効化できる。

### C. センサー等の外部データが必要

- 左右荷重配分・接触反力の正解: 圧力インソール（左右別、時系列）または力センサー付きビンディング。映像との同期（LED・音・タイムコード）。
- 身体質量・用具質量、雪面の傾斜と法線（モード C の力学計算）。
- 選手の同意と倫理手続き（検証データの収集）。

## 3. 実装順序（§7 に対応）

| 手順 | 内容 | 状態 |
|---|---|---|
| 1 | SL・GS の参考映像を調査（URL・種目・撮影方向・用途を記録。学習には使わない） | `docs/wc-reference-and-load-validation.md`（閲覧はできる環境で行う。この環境では映像を視聴できない） |
| 2 | 既存の骨格・板検出精度の評価 | 正解データが無いため未実施。`server/tools/eval.py` で検証セットを作ってから |
| 3 | 荷重推定に必要な観測データの整理 | 本文書 §1・§4 |
| 4 | 推定可能／不可能な物理量の明確化 | 本文書 §1 |
| 5 | 重心移動ベクトルの実装 | 実装（サーバー `vectors` 段階、フロント モード A、書き出し対応） |

| 8 | 再生・スロー・コマ送り・書き出しに対応 | 実装 |

## 4. モード B（荷重傾向）の設計と、有効化の条件

入力（すべて既存の観測・推定値）: ターン方向と局面、外脚・内脚の膝屈曲とその変化率、推定重心と左右足部の横方向の相対位置（正面・背面）、骨盤と足部の相対位置、板の向きの変化（検出時）、重心の移動速さ。

出力: 左右それぞれの「荷重傾向スコア」（0〜1 の相対値、単位なし）と信頼度、`validated: false`。

有効化の条件（色付き矢印・% 表示を解禁する前に満たすこと）:
1. センサー正解との比較で、左右荷重比の時系列相関と、ピーク時刻の誤差が事前に決めた基準（例: 相関 0.7 以上、ピーク誤差 0.1 秒以内。基準値は検証設計で確定）を満たす。
2. SL・GS、側面・正面・背面、複数選手で成立する。
3. 検証に使った動画・センサー・日付・結果を文書化する。

それまでは、矢印は灰色・「参考（未検証）」ラベルのみ、グラフは身体運動指標として表示する。

## 5. WC 選手との比較（§6）

- 比較に使う参照データは、権利を確認した映像を本システムで解析した結果 JSON とする。参照データの作成に YouTube からのダウンロードは行わない。
- 比較は「同じ撮影方向」「同じ種目」「同じターン局面（前半・中盤・後半、切り替え）」に揃え、肩と骨盤の傾斜、左右膝、上体の前傾、板の向き、動作のタイミング（局面ごとの変化量）を並べる。
- 撮影方向が違う場合は数値を並べない。WC 選手を唯一の正解とせず、差の大きい項目を「確認すべき点」として示す。

## 6. 検証方法の提案（要約。詳細は `docs/wc-reference-and-load-validation.md`）

- 圧力インソール（左右別、100 Hz 以上）を履いた滑走を、側面と正面・背面の固定カメラで同時撮影。LED フラッシュまたは音で同期。
- SL・GS 各 10 本以上、複数選手。ターンごとに左右荷重比の時系列、ピーク時刻、切り替え時刻を正解とする。
- 本システムの運動指標・荷重傾向スコアと比較し、§4 の条件で判定する。
