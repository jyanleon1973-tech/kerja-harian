# AI 自動追跡・選手中心ズーム表示 — 調査・設計・実施状況

作成日: 2026-11-01

## 1. 既存コードの調査（追跡精度・表示方法・座標変換）

| 観点 | 現状 | 問題点 | 対応 |
|---|---|---|---|
| 追跡 | `perframe.Tracker`: 前コマの骨格 bbox の周りを正方形に切り出して姿勢推定。体格に対して飛びすぎた検出・骨長が合わない検出を棄却。見失い時は範囲拡大 → タイル探索。対象はタップで指定した 1 名 | 外接領域は関節だけで、板・ストックを含まない。追跡 ID は 1 つだけ（複数人の同時追跡はしない） | `track` 段階で 人物領域・板を含む領域・上半身・足元の 4 種の領域と身体中心、追跡信頼度、状態（det/interp/lost）を出力 |
| 表示 | `<video>` を `object-fit: contain` で表示し、`overlay` キャンバスに正規化座標 × 表示領域で描画（`videoRect()`） | 切り抜き・拡大には `<video>` 直接表示では対応できない | 追尾モードでは `<video>` を透明にし、同じキャンバスに「切り抜いた映像」と「同じ変換を掛けたオーバーレイ」を描く（`composeFrame`） |
| 座標 | 解析データはすべて元動画の正規化座標（板は元動画 px）。表示時にのみ変換 | 問題なし。この方針を維持 | 切り抜きは表示時の変換のみ。解析値は変わらない（テストで確認） |
| 書き出し | ブラウザ: キャンバス合成 + MediaRecorder。サーバー: OpenCV 描画 + FFmpeg | 切り抜き非対応 | 両方に同じ切り抜き変換を実装。出力解像度は元動画のまま（画素を超える拡大は画質を改善しない旨を明記） |
| カメラの動き | `camera` 段階で背景の位相相関によるパンの推定 | ズームは未補正 | 追尾は画像座標で行うため、元映像のパン・ズームは追跡結果に含まれる。自動ズームが見かけの大きさの変化を吸収する |

## 2. 設計（追跡とカメラ制御の分離）

- **AI 側（`server/app/pipeline/track.py: track_frame`）**: 選手 ID、人物の外接領域、身体中心（腰中点）、板・ブーツを含む領域（検出できた板の両端と手首の余白を含む）、上半身領域、足元領域、追跡信頼度、状態。
- **カメラ制御側（`plan_camera`、JS 版 `planCamera`）**: 設定（モード、構図、表示サイズ、拡大率、滑らかさ、中心位置、最大ズーム）から、切り抜き中心・幅・高さ・ズーム倍率を**動画全体を見て**計算する。前後参照の One Euro で揺れを抑え、移動速度（0.6 画面幅/秒）とズーム変化率（1.5 倍/秒）を制限。見失いは最後の位置を約 1 秒保持し、その後は全体表示へ徐々に戻す。切り抜きは常に画面内に収め、最大 4 倍。切り抜き幅が 640px 未満なら「元動画の解像度が不足」を表示。
- **表示**: 通常表示 / 選手追尾 / 追尾＋自動ズーム / スキー板追尾。設定変更は再解析なしで即時反映。モード切替で再生位置は保持。3D 人形・3D 板と同じコマ番号で同期。
- **書き出し**: 現在の表示どおり / 追尾のみ / 追尾＋自動ズーム / 追尾＋骨格 / 追尾＋スキー板 / 追尾＋骨格＋荷重矢印＋数値。サーバー書き出しも `follow` 設定を受け付ける。

## 3. 実施状況

| 要件 | 状態 |
|---|---|
| 選手の自動検出・継続追跡・中心座標・外接領域・大きさの変化・他人との取り違え防止 | 実装済み（既存の追跡 + `track` 段階）。複数人はタップで対象指定。長い見失い後の復帰は近接優先のタイル探索 |
| 雪煙などの一時的な欠落 | 最大 0.4 秒を前後から補間（補間フラグ）。それ以上は「保持 → 全体表示」 |
| 選手を常に中央に、板を切らない余白 | 実装（構図「全身＋板」は板の両端を含む領域に 15% の余白） |
| 自動ズーム（初期 75%）、ユーザー調整（ON/OFF・拡大率・表示サイズ・滑らかさ・中心位置・構図） | 実装 |
| 最大ズームと解像度不足の表示 | 実装（4 倍、640px 未満で警告） |
| 滑らかな追尾（時系列平滑化、急変抑制、パン対応、誤差耐性、前後参照） | 実装 |
| オーバーレイの同期（骨格・肩骨盤線・重心・板・ブーツ・数値・矢印・ターン） | 実装（映像とオーバーレイに同じ変換。数値は元座標で計算し変化しない） |
| スロー・コマ送り・シーク・区間ループ | 実装（コマ番号で駆動。再生中は毎描画で切り抜きを更新） |
| 追尾動画の保存（MP4、プリセット） | 実装（ブラウザ MediaRecorder、サーバー FFmpeg） |
| 実際の SL/GS 映像での検証 | **未実施**（映像なし）。合成動画（小さく映って左から右へ動く人物）で、腰中点が表示の中央（0.50, 0.50）に来ること、ズーム上限、見失い時の保持と復帰、解像度不足の表示、書き出しを確認 |

テスト: サーバー側 28 件合格（追跡領域に板が含まれる、カメラ軌道が選手を追い画面内に収まり急変しない、追尾のみはズーム 1、見失い時の保持と復帰、解像度不足フラグと最大ズーム、API の `track`/`cam` 出力、追尾付き書き出し）。ブラウザ結合テストで、4 モードの切替と再生位置の保持、設定の即時反映、スロー再生中の追尾、追尾＋骨格＋矢印＋数値の書き出しを確認。
